## Routing table (written before implementation)

Outcome vocabulary:

- **COMPOSER**: the presented page composer becomes the key's destination; printable input is observed in its normal `beforeinput`/`input` pipeline.
- **OWNER-CONSUMED**: the named menu, dropdown, disclosure, overlay, or presented control handles the key and has a visible state/focus/action result.
- **IGNORED**: no owner prevents the key or changes action, focus, selection, open state, draft, route, or request count.
- **OVERLAY-FENCED / IGNORED**: the modal prevents rerouting to the composer, but the overlay itself does not consume the key. This is intentionally different from **OWNER-CONSUMED**.

Every bracketed ID below owns one fresh real-browser `it(...)`. Each test starts from a fresh component state, obtains locators again after every render/navigation, and uses real hover/focus/open flows. No synthetic `tabindex`, expando `open`, stale element handle, or reused dropdown typeahead query.

## Contract evidence read before the table

- `/new` registers its page-level capture listener but currently delegates only to picker handling: `ui/src/pages/new-session/new-session-page.ts:229`, `ui/src/pages/new-session/new-session-runtime.ts:59`.
- The composer gives invocation menus first refusal, then applies its Enter submission policy, while other input remains native: `ui/src/pages/new-session/composer.ts:380`.
- `/new` place menus are `wa-popover` plus native buttons: `ui/src/pages/new-session/where-chip.ts:136`, `ui/src/pages/new-session/cloud-target.ts:33`.
- The real agent selector is a Web Awesome dropdown and focuses the selected/first real item after opening: `ui/src/pages/new-session/target-controls.ts:19`, `ui/src/components/agent-select.ts:133`.
- Model selection is native `<details>` with a search input that owns Enter, Escape clearing, and Up/Down highlighting: `ui/src/pages/chat/components/chat-model-picker.ts:187`, `ui/src/pages/chat/components/chat-model-picker.ts:353`.
- App modal presence is recorded by the modal owner, while Web Awesome supplies true modal focus and Escape dismissal: `ui/src/components/modal-dialog.ts:8`, `ui/src/components/modal-dialog.ts:160`.
- Chat reply context menus own Escape and native button activation, but have no typeahead or arrow policy: `ui/src/pages/chat/components/chat-thread-interactions.ts:488`.
- Retained panes become `inert`, `aria-hidden`, inactive, and unpresented; presentation loss is the lifecycle owner for transient cleanup: `ui/src/pages/chat/chat-page-pane-render.ts:68`, `ui/src/pages/chat/chat-pane-retained-presentation.ts:44`.
- Web Awesome 3.11.0 is pinned by `ui/package.json:12`. Direct dependency source inspection confirmed that an open dropdown consumes only matched printable typeahead, Up/Down, focused-item fresh-query Space/Enter, submenu Left/Right, and top-dismissible Escape; unmatched printable keys are not prevented. Its document listeners live only while open.
- Direct dependency source inspection also confirmed that `wa-popover` owns top-dismissible Escape but delegates ordinary button input, and `wa-dialog` uses `showModal()` plus top-dismissible Escape.
- The same dropdown source keeps its document key listener and accumulated typeahead state while open. Therefore an unmatched handoff must close the page-owned dropdown, or a later matching printable can be consumed after the one-second query reset.

Existing-solution preflight: the repo already has the needed owners (Chat's scoped composer policy, native controls, Web Awesome component contracts, modal-layer registry, and retained-pane lifecycle). No new dependency, plugin, service, config, or custom menu implementation is justified.
